# Statuses

Statuses let you mark items with a colored dot (Triage, In progress, Complete…) without ever moving a file. A status belongs to an item *in the explorer*, not to a folder on disk.

## Status sets

Create any number of named **status sets** in **Settings → Atlas Explorer → Status**. Each holds an ordered list of statuses: a label, a color, and optionally flags marking it **Completed** and/or **Cancelled**. Each status row's "more actions" menu makes it the set's default, marks it completed or cancelled, reorders it, or removes it. A status that no longer exists falls back to the set's default.

Other settings on that tab:

- **Color palette**: a shared set of swatches offered by every status color picker, alongside a fully custom color.
- **Glow**: a soft glow around status dots.
- **Retain icons**: keeps the item's normal type icon visible, shrunk inside the status dot, instead of replacing it.
- **Retained icon color**: only matters when Retain icons is on. Match the icon to normal text color, or to the app's background color.

## Assigning statuses

A bucket item with children (a unit or a Folder; the option only appears when there's something underneath it) has a **Statuses** entry on its right-click menu. The **view name** has the same entry for the top level of the whole view (also only when the bucket has something in it). Both open the same dialog. The item that holds the assignment is the **governor**: its status set applies to its *children*, never to itself.

- **Enable statuses**: the master toggle. Everything else is greyed out (but kept) while it's off.
- **Status set**: which set governs this item's (or the view's) children.
- **Inherit to subfolders**: off by default. When on, the assignment cascades past direct children all the way down the tree, until a closer item has its own assignment, which then takes over for its own subtree. The nearest governor wins, like CSS.
- **Hide completed** / **Hide cancelled**: hide items whose current status is flagged as one or the other, entirely (not just folded). An item matching the active filter is shown anyway.
- **Apply statuses to**: which kinds of item underneath receive a dot: blocks, files, modules (real folders), or Folders (the organizational kind).
- **Sort children by status**: orders the governed children by their status, ranked by each status's position in the set (top of the set sorts first). Items sharing a status keep their existing relative order. **Reverse order** flips the ranking. You can also pick **Status** from **Sort children…** (see [Sorting](sorting.md)).
- **Truncate statuses**: once at least two of a governor's children share a truncation-enabled status, they collapse into one placeholder row (the status's dot plus a count and label: a custom label if set, otherwise a pluralized form of the status's label). Click the placeholder to expand the individual rows (a **Collapse** row folds them again). Expanded or collapsed state resets on reload. An item matching the filter is always shown on its own, and the placeholder's dot never shows a retained type icon, since a group can mix types.

**Hide always beats truncate:** a hidden item is never counted in, or shown as part of, a truncated group.

Inbox items can't have a status; place them in the bucket first.

## Changing one item's status

**Click a status dot** to open a small popup listing every status in the governing set with its color. Pick one to change that item's status, independent of its siblings. Clicking the row itself still opens the item, and right-clicking still opens the full menu. For a module whose icon is currently a status dot, **View module contents** moves to its right-click menu, because clicking the icon now means "change status".

There is no "clear override" control, and no double-click on the dot.

Statuses also work on rows generated by a [data source](data-sources.md), and an agent can read and write them through the [MCP server](mcp-server.md).
